The principle

Evidence, not assumptions.

Passing tests matter, but they don't automatically prove a change is correct, safe, or understood. Make reasoning and evidence part of the review itself.

01 / INSPECT

Understand the repository

Read project guidance, conventions, Git state, tests, build scripts, and existing safeguards before proposing changes.

02 / CHALLENGE

Review independently

Use a clean reviewer context to examine the actual diff, challenge assumptions, and report actionable findings.

03 / VERIFY

Prove the exact change

Run real checks, tie results to the precise change, and disclose what was not tested or cannot be guaranteed.

The workflow

From task brief to informed approval.

A clear sequence that keeps the developer in control and makes review outcomes traceable.

01 · InspectRead instructions and project state.
02 · AgreeDefine scope and acceptance evidence.
03 · ImplementMake the smallest agreed change.
04 · VerifyRun checks and independent review.
05 · UnderstandExplain the diff before approval.

Project status

Open development. Honest limitations.

This project is an engineering workflow aid, not a security certification or a guarantee that software is defect-free. Adapt checks to your stack, keep credentials out of logs, and never claim a check ran unless it really did.
